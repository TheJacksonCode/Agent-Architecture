# Media Prompts dla NotebookLM Studio - Claude Code Hooks Best Practices 2026

Ten plik zawiera prompty gotowe do wklejenia w NotebookLM Studio (tryb "Customize" dla Video Overview oraz tryb infografika). Kazdy prompt to 2 akapity zgodne z polami NotebookLM:

- **Akapit 1: Styl wizualny** - niestandardowy styl wizualny materialu (paleta, typografia, kompozycja, tempo)
- **Akapit 2: Fokus prezentacji** - na czym maja skupic sie prezenterzy AI (NotebookLM dwa AI-hosty), jakie tematy wyciagnac, jaki ton, jakie konkrety

Dla wideo jeden idealny prompt (kompletny przeglad tematu). Dla infografiki trzy komplementarne warianty, z ktorych mozesz wybrac najlepiej pasujacy do twojego celu (edukacja vs decyzja vs ostrzezenie).

Zrodla wiedzy: wszystkie 3 lekcje (00_FUNDAMENTALS, 01_PATTERNS, 02_DECISION_GUIDE) oraz kanoniczny `plans/SYNTHESIS.md`. NotebookLM powinien miec wszystkie te pliki jako zrodla w notebooku.

## Video Overview (jeden idealny case)

**Akapit 1 - Styl wizualny:**
Minimalistyczne, ciemne motion graphics w paletce granat-cyjan-czerwony-zielen (tlo #0a0e27, kod i dane #00d9ff, alerty i exit-2 blokady #ff4757, zatwierdzenia i exit-0 #7ed321, akcenty pomaranczowe #ff8a3c dla wyroznien). Typografia: Inter Tight dla naglowkow slajdow, JetBrains Mono lub Fira Code dla bloku kodu (16-18 pt, wyrazne podswietlenia exit codes i nazw eventow takich jak PreToolUse czy PostToolUse). Kompozycja: slajdy symulujace edytor kodu i terminal, boczna os czasu sesji Claude Code od SessionStart przez UserPromptSubmit, PreToolUse i PostToolUse do Stop i SessionEnd, z podswietlanymi wezlami w takt narracji. Tempo spokojne ale konkretne, kazdy koncept dostaje 8-12 sekund ekspozycji plus jeden live-snippet bash lub settings.json pisany na ekranie linia po linii (keyboard typing effect). Transitions gladkie horyzontalne wipe. Idealna dlugosc 10-15 minut zeby zmiescic pelny przekroj 28 eventow, 4 typow handlerow, exit codes, 5 warstw precedensji settings i TOP 5 wzorcow plus TOP 5 anty-wzorcow. Zadnej muzyki tla lub bardzo stonowany ambient zeby nie konkurowal z glosami prezenterow AI.

**Akapit 2 - Fokus prezentacji:**
Prezenterzy AI powinni traktowac to jako kompletny kurs wprowadzajacy doswiadczonego developera w hooki Claude Code od zera do praktycznego zastosowania. Struktura narracji w trzech blokach: (1) Fundamenty - co to jest hook jako deterministyczny callback cyklu zycia sesji AI, 28 eventow pogrupowanych w 8 rodzin, 4 typy handlerow z timeoutami (command 600s, http 30s, prompt 30s, agent 60s), KRYTYCZNA regula exit codes gdzie exit 2 BLOKUJE a exit 1 TYLKO OSTRZEGA (najczestsza pulapka calego ekosystemu, prezenterzy musza to powtorzyc minimum trzy razy w roznych kontekstach). (2) Wzorce - piec najczestszych praktycznych zastosowan z live code snippet: Protect-versions (PreToolUse Bash blokujacy edycje zarchiwizowanych folderow jak v31), Secrets-guard (PreToolUse Edit/Write skanujacy sekrety AKIA i API keys), JSONL observability (PostToolUse async logger eventow z timestamp i exit_code), TTS-notify (Stop + systemowy toast) i PreCompact archive (v2.1.105+ dump kontekstu przed kompakcja). (3) Decyzje i ostrzezenia - drabina precedensji settings Managed > CLI > Local > Project > User ze szczegolnym naciskiem na regule ze permissions.deny z wyzszej warstwy zawsze bije permissions.allow z nizszej, oraz 3 anty-wzorce ktore kosztowaly realnych uzytkownikow godziny pracy: exit 1 zamiast exit 2, command injection przez interpolacje tool_input.command do bash oraz sync observability blokujaca Stop event. Prezenterzy maja byc konkretni, unikac ogolnikow typu "to wazne", zamiast tego cytowac liczby (2 CVE w 2025-2026, 600s domyslny timeout command, 200ms rozsadny budzet PreToolUse, 1M context w Opus 4.6/4.7), wymieniac nazwy eventow dokladnie tak jak w dokumentacji (PreToolUse, PostToolUse, UserPromptSubmit, PreCompact, PermissionDenied) zeby NotebookLM RAG w innych sesjach dobrze znajdowal embeddings. Ton: powazny ale dostepny, a la staszy kolega z zespolu infrastruktury. Brak buzzwordow marketingowych typu "gamechanger" czy "revolutionary" - to dokumentacja dla pracujacych developerow, nie prezentacja sprzedazowa.

## Infografika - wariant 1: Mapa taksonomii eventow (edukacyjny)

**Akapit 1 - Styl wizualny:**
Plakat pionowy A2 (420x594 mm) w ukladzie kolowym mandali technicznej. Paleta ciemna: tlo granatowe #0a0e27, akcenty cyjanowe #00d9ff dla nazw eventow i #ff6b35 dla rodzin. W geometrycznym centrum plakatu duze logo "Claude Code Hooks" z 4 ikonami handler types (command, http, prompt, agent) w formie zaokraglonych kwadratow. Wokol centrum, rozmieszczone w 8 segmentach tarczy zegara, rodziny eventow opatrzone ikonami line-art: (12:00) Session z eventami SessionStart / SessionEnd / UserPromptSubmit / Notification, (1:30) Prompt, (3:00) Tool z PreToolUse i PostToolUse, (4:30) Agent, (6:00) Permissions z PermissionDenied, (7:30) Notification, (9:00) Compact z PreCompact i PostCompact, (10:30) Konfiguracyjne z Git / MCP / Plan. Kazdy event to maly zaokraglony kafelek z nazwa pisana JetBrains Mono 12 pt plus jednolinijkowy opis funkcji pod nazwa czcionka Inter 9 pt. Po prawej stronie plakatu pionowa kolumna "EXIT CODES" z 3 kartami w skali wzrastajacej kolorystycznie: exit 0 zielony, exit 1 zolty z ostrzezeniem "NIE BLOKUJE - PULAPKA!", exit 2 czerwony z oznaczeniem "BLOCK". U dolu plakatu pasek piramidy ukladu precedensji Managed > CLI > Local > Project > User w 5 odcieniach intensywnosci. Typografia: Inter Tight Black 24-48 pt dla naglowkow, Inter 9-12 pt dla opisow, JetBrains Mono dla kodu, wszystko white on dark. Marginesy 30 mm, gutter 8 mm miedzy segmentami. Format do druku CMYK 300 DPI plus wersja ekranowa SVG.

**Akapit 2 - Fokus prezentacji:**
Infografika ma uczyc calego ekosystemu eventow Claude Code na jeden rzut oka - to mapa referencyjna dla developera ktory wklada ja do biurka i patrzy kiedy projektuje hooka. Najsilniejszy punkt wizualny to kolo eventow z 28 nazwami, bo to najcenniejsza informacja ktora jest rozproszona w oficjalnej dokumentacji. Prezenter AI podczas audio overview tej infografiki powinien przeprowadzic sluchacza przez 8 rodzin eventow jedna po drugiej, podajac 1 konkretny use case per rodzine (Session -> TTS notify, Prompt -> context injection, Tool -> protect versions, Agent -> delegation, Permissions -> audit trail, Notification -> toast, Compact -> archive, Konfiguracyjne -> MCP gate). Drugi nacisk to EXIT CODES jako odrebny wizualny blok w kolumnie po prawej - prezenter powinien powiedziec 3 razy w roznych kontekstach regule "exit 2 blokuje, exit 1 nie blokuje" i przywolac przyklad ze developer tracacy 2 godziny na debugowaniu hooka ktory mial exit 1. Trzeci nacisk to piramida precedensji u dolu z regula "deny wyzszej warstwy zawsze wygrywa" - to sedno modelu bezpieczenstwa. Ton prezentacji: akademicki ale konkretny, cytowanie dokladnych nazw eventow (PreToolUse, PostToolUse, PreCompact) minimum 3 razy kazda zeby embedding coverage w NotebookLM RAG byl dobry. Unikac meta-komentarzy typu "ta infografika jest super" - mowic o zawartosci, nie o formie.

## Infografika - wariant 2: Drzewo decyzyjne "jaki hook wybrac" (praktyczny)

**Akapit 1 - Styl wizualny:**
Plakat pionowy A1 (594x841 mm) z dominata kompozycyjna w postaci duzego drzewa decyzyjnego organicznie rozgaleziajacego sie od korzenia u gory do lisci u dolu. Paleta kontrastowa jasna: tlo biale lub bardzo jasny beton #f5f5f7, drzewo w ciemnym granacie #1a1d35, akcenty zielone #34c759 dla rekomendowanych sciezek i czerwone #ff3b30 dla sciezek ostrzegawczych. Korzen u gory: prostokatny node z pytaniem "Chcesz zmodyfikowac zachowanie Claude Code?" Inter Display Black 36 pt. Pierwsza decyzja rozgaleza sie na dwie grube galezie: lewa (grubsza, rekomendowana jesli runtime-zalezna logika) prowadzi do hookow, prawa (cienniejsza) prowadzi do 5 alternatyw (permissions.deny / skill / command / agent / CLAUDE.md). Lewa galaz rozgaleza sie dalej w 8 sub-decyzji z explicit pytaniami: "Chcesz zablokowac? -> PreToolUse + exit 2", "Chcesz zalogowac? -> PostToolUse + async:true", "Chcesz dopisac kontekst? -> UserPromptSubmit + additionalContext", kazda konczaca sie node-lisciem z konkretna rekomendacja eventu i 3-liniowym snippetem bash lub JSON w ramce monospaced czarnej na bialym. Po prawej stronie plakatu pionowa tabela "PERFORMANCE BUDGETS" z 4 wierszami (Tier 1 <100ms / Tier 2 <500ms / Tier 3 <2000ms / Tier 4 <5000ms) i krotkim case study kazdego tieru. U dolu plakatu pasek "ANTI-PATTERNS KTORE KOSZTUJA" z 3 czerwonymi kartami (exit 1 zamiast exit 2, command injection, sync observability), kazda z jednolinijkowym fixem. Typografia: Inter Display Black 24-36 pt dla naglowkow node'ow, Inter 11-14 pt dla opisow galezi, JetBrains Mono 10 pt dla snippets. Linie drzewa grube 2-3 mm, wiazka od korzenia 4 mm zwezajaca sie do 1.5 mm na lisciach.

**Akapit 2 - Fokus prezentacji:**
Infografika ma odpowiadac na pytanie "jak wybrac odpowiedni mechanizm do mojego problemu" - to narzedzie decyzyjne, nie encyklopedia. Prezenterzy AI powinni zainscenizowac 3 scenariusze uzytkownika i przejsc przez drzewo z kazdym: (1) "Chce zablokowac edycje plikow v31 bo to archiwum" - prowadzisz sluchacza od korzenia przez "runtime-zalezna? TAK" przez "zablokowac? TAK" do lisc "PreToolUse + grep + exit 2", cytujesz 3-liniowy snippet. (2) "Chce widziec co Claude robi z moimi plikami" - sciezka do "PostToolUse + async:true JSONL logger", podkreslasz waznosc async:true bo sync blokuje Stop event. (3) "Chce zeby tylko ja mogl wlaczyc niebezpieczne komendy" - ale tu SKRECASZ na prawa galaz "alternatywy" i pokazujesz ze permissions.deny w Managed layer jest tansze i bezpieczniejsze niz custom PreToolUse hook, bo deny jest nieobchodzalne a hook mozna wylaczyc edytujac settings.json. Ta kontraintuicyjna rekomendacja to serce plakatu - prezenterzy powinni powiedziec explicite "nie wszystko wymaga hooka, czesto prostsze narzedzie wygrywa". Drugi nacisk to performance budgets po prawej - cytowac case study ruvnet/ruflo gdzie 7s latency PreToolUse blokowalo uzytkownikow, fix = async logger 200ms. Trzeci nacisk u dolu to 3 anti-patterny czerwone - pokazac kazdy z 15-sekundowym mini-case study. Ton: pragmatyczny senior engineer, prezenter powinien uzywac liczby i concrete file paths zamiast abstrakcji.

## Infografika - wariant 3: Sciana anti-patterns i hardening checklist (ostrzegawczy)

**Akapit 1 - Styl wizualny:**
Plakat poziomy A2 (594x420 mm) jako sciagawkowa sciana bezpieczenstwa w stylu post-mortem incident review. Paleta trojkolorowa z mocnym kontrastem: tlo czarne #0a0a0a, czerwone #ff3030 dla anty-wzorcow, zielone #30d060 dla fixow, biale dla naglowkow i neutralnego tekstu. Gorna polowa plakatu: siatka 6x3 z 18 antiwzorcami, kazdy w formie karty 90x110 mm z czarnym tlem i czerwonym topstripe, (u gory nazwa anty-wzorca w Inter Display Black 14 pt np. "exit 1 zamiast exit 2 blokuje", ponizej ikona bledu line-art 48x48 px z przekresleniem, dalej zly kod 2-liniowy w czerwonej ramce monospaced 10 pt, pod nim poprawny kod 2-liniowy w zielonej ramce, na dole mini-label z kosztem bledu np. "utrata 2h pracy" lub "command injection CVSS 8.7"). Dolna czesc plakatu podzielona na dwie kolumny: po lewej piramida hardening 5 warstw (Layer 1 Input validation / Layer 2 Sandbox / Layer 3 Least privilege / Layer 4 Audit / Layer 5 Fail-closed) kazda z 3-punktowa checklista, po prawej sekcja "CVE NOTES 2025-2026" z 2 kartami (CVE-2025-59536 CVSS 8.7 command injection, CVE-2026-21852 CVSS 5.3 HTTP hook leak) z krotkim opisem i statusem verified. Typografia: Inter Display Black 18 pt dla nazw antiwzorcow, JetBrains Mono 10 pt dla bloku kodu, Inter 9 pt dla opisow. Wyrazne separatory miedzy kartami 4 mm gutters. Nad plakatem duzy naglowek "18 ANTI-PATTERNS I 5 WARSTW HARDENING - CLAUDE CODE HOOKS 2026" w Inter Display Black 48 pt na czerwonym pasku. Akcenty typograficzne: regula zlota "exit 2 blokuje - exit 1 NIE blokuje" w czerwonej ramce na srodku dolnej czesci, Inter Display Black 24 pt. Forma do druku na sciane zespolu dev plus wersja webowa.

**Akapit 2 - Fokus prezentacji:**
Infografika ma uczyc przez negatywne przyklady - to plakat ostrzegawczy, nie optimistyczny. Prezenterzy AI powinni przyjac ton post-mortem senior engineera po incydencie: powazny, konkretny, cytujacy liczby. Struktura narracji w dwoch blokach: (1) TOP 5 najbardziej bolesnych antiwzorcow z 18 na plakacie, kazdy dostaje 30 sekund ekspozycji z nazwa, ekspozycja zlego kodu, ekspozycja fixu i podanie konkretnego kosztu bledu. Pierwszy anti-pattern to OCZYWISCIE "exit 1 zamiast exit 2 blokuje" bo to pulapka nr 1 calego ekosystemu i wymaga powtorzenia 3 razy w roznych kontekstach. Drugi to "command injection przez bezposrednia interpolacje tool_input.command do bash" - fix to quoted env vars plus jq dla JSON parsing, koszt CVE-2025-59536 z CVSS 8.7. Trzeci to "sync observability blokujaca Stop event" - fix async:true, koszt 5s latency UX impact. Czwarty "allowedHttpHookUrls pusty lub za szeroki" - fix pin to Managed settings, koszt CVE-2026-21852 z wyciekiem danych. Piaty "brak set -euo pipefail w bashu" - fix dodac do shebang, koszt silent failure. (2) Hardening pyramid 5 warstw - prezenter przechodzi od szczytu do podstawy, kazda warstwa dostaje 20 sekund: Input validation z reqirement "quote CLAUDE_PROJECT_DIR zawsze", Sandbox z regula "jq dla JSON, Python dla bash komend", Least privilege z "allowedHttpHookUrls pinned to Managed layer", Audit z "JSONL logger na kazdym evencie z session_id correlation", Fail-closed z "na niepewnosc blockuj zamiast puszczac". Prezenterzy powinni cytowac case studies: "deweloper ruvnet/ruflo stracil 7 sekund latency przez synchroniczne logowanie", "CVE-2025-59536 wymagal pilnego patcha w claudekit w marcu 2025", "fork bomba Blake Crosley pokazala ze proste regex blacklisty sa bypassable". Ton: powazny ale bez straszenia, prezenter konkretny i bazujacy na liczbach. Unikac ogolnikow jak "byc ostroznym" - zastapic precyzyjnym "uzywaj allowedHttpHookUrls pinned to Managed layer by default, exit 2 nie 1, set -euo pipefail zawsze, async:true dla telemetrii".

## Jak uzywac w NotebookLM Studio

1. Upewnij sie ze notebook ma wszystkie zrodla: `00_FUNDAMENTALS.md`, `01_PATTERNS.md`, `02_DECISION_GUIDE.md` i opcjonalnie `plans/SYNTHESIS.md` dla glebszych cytatow.
2. Wybierz tryb (Video Overview albo infografika - NotebookLM ma dedykowane pola customize w sekcji Studio).
3. Skopiuj akapit 1 do pola "Visual Style" (lub odpowiednika) i akapit 2 do pola "Focus" / "Topic for presenters".
4. Dla infografiki zdecyduj ktory z 3 wariantow pasuje do celu: wariant 1 edukacyjny ogolny, wariant 2 decyzyjny praktyczny, wariant 3 ostrzegawczy skupiony na bezpieczenstwie.
5. Wygeneruj - jesli wynik nie trafia w ton, doprecyzuj akapit 2 (fokus) nie akapit 1 (styl) bo styl dziala dobrze a fokus jest bardziej wrazliwy na interpretacje AI.

Rekomendacja startowa: Video Overview + Infografika wariant 1 (mapa taksonomii) daje najlepsze pokrycie edukacyjne dla nowego uzytkownika hookow. Infografika wariant 2 (drzewo decyzyjne) dla zaawansowanego developera ktory ma konkretny problem do rozwiazania. Wariant 3 (anti-patterns) dla zespolu security review lub onboardingu do produkcyjnego uzycia.
